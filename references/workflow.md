# 七步工作流（WorkBuddy 适配）

质量大部分在写代码之前就定掉了。拿到 UI 需求后，按顺序走，每一步先想清楚再落笔。

## 1. 媒介与落点（Medium & Place）
- 它是**静态构图**还是**短动画**（10–16 秒循环最稳）？放在页面的哪个区块（hero / 功能卡 / 文档头部）？
- 实际出现的**尺寸**是多少？手机端单独设计一版（约 358px 宽），不要直接挤压桌面版。
- 决定后立刻定**裁切框**：视线要落在哪，边缘让什么"出血"或"跨骑"。

## 2. 外观（Look）
- 先定四选一基调：**浅色 / 深色 / 蓝图 / 玻璃质感**。
- 只选**一个强调色**，配**安静的中性底**（暖灰 / 米白 / 墨黑）。多强调色 = 立刻"平淡"的反面（杂乱）。
- 决定保真度：是精致营销页，还是草图感？

## 3. 故事（Story）
- 写 **3–5 个节拍**：UI 要"讲"什么？例如官网：到达 → 看见课程 → 遇见教练 → 加入 → 找到我们。
- 每个节拍对应一个视觉焦点。没有故事，界面就是一堆控件。

## 4. 示例（Example）
- 从 `gold-examples.md` 里挑**最接近**的组合模式起手，而不是从空白写。
- 改它，而不是重写它。

## 5. 屏幕（Screen / 真字符串预算）
- 只在**故事焦点**放真实文字（标题、关键数据、一个 CTA）。
- 其余用**占位条（placeholder bars）**或留白填充；空荡的角落、为填满而拉开的行距、悬浮在底板上的窗口，都显得"未完成"而非"克制"。
- 简化文字，**不是简化上下文**：结构要完整，信息要少。

## 6. 编排（Choreography）
- 节拍**重叠**进行，而不是排队；循环要**首尾相接**，看不出接缝。
- 每个动效都要能回答"它为什么动"（因果）：
  - 呼吸缩放 = 平静（瑜伽 / 冥想类天然适配）
  - 滚动揭示 = 引导视线，分批错落而非整齐划一
  - hover 抬升 + 描边生长 = "可点"
- WorkBuddy 没有原版的 Act API：用 CSS `@keyframes` / `transition` 与原生 `IntersectionObserver` 实现，禁用 `Math.random()` 与无种子的随机，保证可复现。

## 7. 排练（Rehearse / 拍片自检）
- 没有 `film.mjs`，用 `checklist.md` 逐条过。
- 必要时起本地静态服务器，用浏览器截图核对：单帧跳变、文字溢出框、循环接缝、层级是否聚焦。
- 修掉发现的问题，再交付。
