# 排练自检清单（替代 film.mjs）

原版用 `film.mjs` 把 demo 录成 contact sheet 逐帧检查。WorkBuddy 没有该脚本，用这份清单做等效"拍片自检"。交付前逐条过，任一条中招就修。

## A. 构图与层级
- [ ] **不是装框**：有元素跨骑边缘 / 重叠 / 出血，而非整窗缩进卡片。
- [ ] **不是扁平**：有明确主角（尺度/色彩/阴影拉开），视线知道先看哪。
- [ ] **不是线框**：结构完整、有真实品牌底色与可辨识信号。
- [ ] **不是太满**：真实可读句子 ≤ 3–5 处，其余占位或留白。
- [ ] **不是平淡**：brief 要的外观 + 一个强调色已兑现。

## B. 文字与溢出（截图核对）
- [ ] 没有文字溢出容器 / 被截断 / 撑破卡片。
- [ ] 标题在容器宽度内自然换行，无孤字成行。
- [ ] 占位条长度有变化，不像"同样长的灰块"。

## C. 动效（因果）
- [ ] 每个动画都能回答"为什么动"；没有为动而动。
- [ ] 循环首尾相接，看不出接缝（尤其 hero 呼吸 / 数字滚动）。
- [ ] 没有单帧跳变（transition 时长一致、缓动统一）。
- [ ] 动效时长克制（揭示 0.6–0.9s，hover 0.3–0.5s）。

## D. 适配与可达性
- [ ] 移动端单独成立（约 358px 宽不挤压，导航可收起）。
- [ ] 尊重 `prefers-reduced-motion`：关闭动画后内容仍完整可读。
- [ ] 对比度达标，强调色不只靠颜色传达信息。

## E. 真字符串预算
- [ ] 真实文案只出现在故事焦点（标题 / 1 个关键数据 / 1 个 CTA）。
- [ ] 没有"为填满而拉开间距的行"或"悬浮在底板上的孤立窗口"。

## 怎么"拍"
1. 起本地静态服务：`python3 -m http.server 8011`（在站点目录）。
2. 用浏览器打开，截首屏与每个 section。
3. 逐帧感：把 hero 动画暂停在 0% / 50% / 100%，确认无跳变、无溢出。
4. 缩到手机宽度再截一遍。
